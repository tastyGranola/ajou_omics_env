# 세션 A — plan-and-execute

실행 위치: `worktrees/plan-execute/`

```bash
cd worktrees/plan-execute && claude
```

---

## 이 프롬프트가 이렇게 생긴 이유

형식은 Biomni 논문 보충자료(Science 393, eadz4351) Section L 의 분석 지시 프롬프트를
따랐습니다. `Task` / `Objective` 머리말, `Path` 블록, `1 / 1.1` 소수점 번호가 그것입니다.

핵심은 **무엇을 원하는지만 적고, 어떻게 할지는 적지 않는다**는 것입니다.

| 적는다 | 적지 않는다 |
|---|---|
| 답하려는 질문 | 쓸 함수 이름과 파라미터 값 |
| 데이터가 어디 있는지 | HVG 를 몇 개 뽑을지 |
| 무엇이 산출물로 남아야 하는지 | resolution 을 얼마로 할지 |
| 비교를 위해 지켜야 할 형식 | 어떤 통계 검정을 쓸지 |

오른쪽 칸은 **Claude 가 정할 일**입니다. 그걸 다 적어 주면 LLM 을 쓰는 의미가 없습니다.
대신 **정한 것을 기록하게** 합니다 — 그 기록이 나중에 비교의 재료가 됩니다.

번호는 좌표입니다. 결정 로그와 검증 리포트가 `3.2` 처럼 번호로 서로를 가리킵니다.

## 여는 프롬프트 — 그대로 붙여 넣으세요

```
Task       IFN-beta 자극에 대한 PBMC 세포 타입별 반응 분석
Objective  IFN-beta 자극을 받은 PBMC 는 세포 타입별로 어떻게 다르게 반응하는가.
           유전자 수준과 경로·전사인자 수준에서 각각 답한다.

Dataset    GSE96583 batch2 — PBMC, 도너 8명, ctrl / stim 두 조건.
           약 12,000 세포 × 14,391 유전자. .X 는 raw count.
           obs: stim · donor · total_counts · n_genes. 세포 타입 주석은 없다.

Path       입력    data/processed/gse96583_ifnb.h5ad
           참조    data/genesets/                 gene set · footprint 캐시
                   core_markers.xlsx              annotation 검증용
                   parallel_lab/CHEATSHEET.md     decoupler 2.x API
           작업    이 작업 트리. 모든 중간 데이터·그림·로그를 여기에만 쓴다.

Rules
  R1  전체 계획을 체크박스 목록으로 먼저 보여주고 승인을 받는다.
      승인 후에는 묻지 않고 끝까지 실행하며, 한 단계를 끝낼 때마다 목록을 갱신한다.
      계획을 벗어나야 하면 멈추지 말고 [✗] 와 이유를 적은 뒤 수정된 단계를 넣고 간다.
  R2  판단이 갈리는 지점을 만나면 스스로 정하고, 무엇을 왜 골랐는지와 고르지 않은 대안을
      EXPERIMENT.md 결정 로그와 metrics.json 의 decisions 에 항목 번호와 함께 남긴다.
  R3  수치를 지어내지 않는다. 없으면 없다고 적는다. 추정치를 실측치처럼 쓰지 않는다.
      단계마다 무엇을 했고 어떤 값이 나왔는지 print 한다. 그림은 절대 경로를 print 한다.
  R4  각 단계가 끝나면 step-validator 서브에이전트를 부른다.
      결과를 results/validation/<번호>_<단계>.md 에 저장하고 metrics.json 에 점수를 누적한다.
      FAIL 이면 다음으로 가지 말고 고친 뒤 다시 검증한다.
  R5  decoupler 는 2.x 다. 기능 분석 코드를 짜기 전에 CHEATSHEET.md 를 읽는다.


1   QC
1.1 필터를 걸기 전에 n_genes · total_counts 분포를 본다.
1.2 컷오프를 정한다. 잘려나가는 세포가 어떤 세포인지 먼저 확인한다.
1.3 필터 단계별 잔존율과 stim / ctrl 균형을 표로 남긴다.

2   정규화 · HVG · 차원축소
2.1 정규화 후 log-normalized 행렬을 layer 나 .raw 에 보존한다. 6·7 단계에서 쓴다.
2.2 HVG 선별 → scaling → PCA. 이후 쓸 PC 개수를 variance ratio 로 정한다.

3   배치 통합
3.1 obs 의 컬럼을 출력해 배치 후보 변수가 무엇인지 먼저 확인한다.
3.2 보정 여부와 batch_key 를 정한다. stim 은 관심 조건이지 배치가 아니다.
3.3 IFN 반응 유전자(ISG15 · IFI6 · MX1 · IFIT1 등)의 조건 간 발현 차이를
    보정 전후로 나란히 표에 남긴다. 그림만 보고 넘어가지 않는다.

4   Clustering
4.1 resolution 을 여러 값으로 돌리고 클러스터 수와 최소 크기를 표로 남긴다.
4.2 하나를 고른다. 근거는 4.1 의 수치로 댄다.

5   Annotation
5.1 클러스터별 marker 를 뽑아 세포 타입을 붙이고, 근거 marker 를 함께 적는다.
5.2 core_markers.xlsx 와 대조한다. 불일치 항목을 빼지 않는다.
5.3 근거가 약한 클러스터는 unassigned 로 남긴다.
5.4 PBMC 에서 기대되는 주요 타입 중 나오지 않은 것이 있으면 목록으로 적는다.

6   조건 간 차등발현
6.1 세포 타입 안에서 stim vs ctrl 을 비교한다. 전체 세포를 한 번에 비교하지 않는다.
6.2 검정 입력은 2.1 의 log-normalized 다. 배치 보정된 임베딩을 쓰지 않는다.
6.3 세포 수가 적은 타입의 결과에 저신뢰 표시를 한다.
6.4 세포 단위 검정이 같은 도너의 세포를 독립 표본으로 취급한다는 한계를 적는다.

7   조건 간 기능 분석
7.1 data/genesets/ 에서 gene set 과 footprint 를 읽는다.
    집합 수 · 크기 분포 · 데이터 유전자와 겹치는 수를 표로 남긴다.
7.2 세포 타입 안에서 (donor × stim) pseudobulk → DE → 그 통계량으로 농축을 돌린다.
    도너 8명이 조건마다 다 있으므로 여기서 6.4 의 한계가 해소된다.
7.3 세포 수준 점수도 낸다. 세포 수준과 조건 대비가 다른 질문에 답한다는 것을 명시한다.
7.4 gene set 을 둘 이상, 통계 방법을 둘 이상 써서 돌리고
    상위 결과가 얼마나 일치하는지 표로 남긴다. 무엇을 바꿨을 때 더 갈렸는지 적는다.
7.5 IFN-beta 자극이므로 인터페론 반응이 상위여야 한다.
    상위 10위 안에 없으면 해석하지 말고 멈추고, 앞 단계를 조사한다.
7.6 상위 경로의 leading edge 유전자와, 상위 집합끼리의 중복을 확인한다.
    중복된 집합을 서로 다른 발견으로 세지 않는다.
7.7 6단계 DEG 개수와 7.2 의 pseudobulk DEG 개수를 세포 타입별로 나란히 놓는다.
7.8 세포 타입 × 경로 점수 행렬을 남긴다. 이것이 Objective 에 답하는 자리다.

8   REPORT
8.1 핵심 요약 ≤200단어 — 목적 · 데이터 · 방법 · 주요 발견.
8.2 주요 결과 — 세포 타입별 DEG 와 상위 경로, 조건 간 차이. 주장마다 근거 각주.
8.3 그림 요약 — QC · 보정 전후 UMAP · resolution 패널 · DEG · 세포타입×경로 heatmap.
8.4 방법·QC 부록 — 파라미터 표, 패키지 버전(실측), 단계별 잔존율, 실행 시간·메모리.


Expected Output
  단계마다 그 단계를 재현할 수 있는 산출물이 남아 있어야 한다 — 쓴 파라미터,
  중간 수치, 그림, 그리고 그렇게 정한 근거.
  results/validation/ 에 단계별 검증 리포트 (1~8 단계 각각).
  EXPERIMENT.md 결정 로그에 판단이 갈린 지점이 항목 번호와 함께 빠짐없이.

Output Format
  results/  · figures/  아래에 단계별로 정리한다. 하위 디렉토리 이름은 스스로 정한다.
  results/summary/metrics.json   parallel_lab/metrics_template.json 의 키 이름을 지킨다.
                                 다른 실험과 비교하는 파일이므로 키를 바꾸지 않는다.
  results/summary/report.html    8단계의 네 절.


먼저 위 요구사항을 반영한 전체 실행 계획을 R1 의 체크박스 목록으로 세워서 보여줘.
각 단계에서 네가 정해야 하는 판단이 무엇이고 어떤 선택지가 있는지도 계획에 같이 적어줘.

내가 계획을 승인하면 그 다음부터는 나에게 묻지 말고 끝까지 실행해.
```

**plan mode** 를 쓰면 더 분명해집니다. 붙여 넣기 전에 `Shift+Tab` 을 두 번 눌러
`plan mode` 로 바꾸면 Claude 는 파일을 고치지 않고 계획만 세웁니다.

## 계획을 받으면 이것부터 보세요

프롬프트가 방법을 지정하지 않았으니, **계획서가 곧 Claude 의 방법 선택**입니다.
거기서 결과를 가장 크게 좌우하는 세 군데를 확인하세요.

| | 볼 것 |
|---|---|
| `3.2` | `stim` 을 보정하겠다고 되어 있는가. 보정하면 보려던 조건 효과가 지워질 수 있습니다 |
| `4.2` | resolution 을 무엇을 근거로 고르겠다고 하는가 |
| `7.2` | pseudobulk 를 도너 단위로 하겠다고 되어 있는가 |

한 군데만 고쳐도 됩니다. **고쳤다면 무엇을 고쳤는지 기억해 두세요.**
비교할 때 그 한 줄이 결과를 어디까지 바꿨는지 보게 됩니다.

```
좋아. 이대로 진행해.
```

## 실행이 도는 동안

**이 창은 그대로 두고 세션 B 로 넘어가세요.** 기다리지 않습니다.

돌아왔을 때는 마지막 체크박스 목록만 보면 어디까지 갔는지 알 수 있습니다.
`[✗]` 가 있으면 계획을 벗어난 자리입니다 — 거기가 볼 만한 곳입니다.

## 끝났을 때 확인

```
results/summary/metrics.json 과 EXPERIMENT.md 결정 로그가 채워졌는지 확인하고,
빠진 항목이 있으면 채워줘.

그리고 아래를 표로 정리해줘.
  1. 네가 스스로 정한 판단들 — 항목 번호 · 무엇을 골랐나 · 고르지 않은 대안
  2. 단계별 검증 점수(정확성 · 완결성)와 WARN 으로 남겨 둔 것, 왜 고치지 않았는지
  3. 7.4 에서 gene set 을 바꿨을 때와 방법을 바꿨을 때 중 어느 쪽이 결과를 더 바꿨나
```

## 검증자는 무엇을 하나

`step-validator` 는 이 저장소에 정의된 **읽기 전용 서브에이전트**입니다
(`.claude/agents/step-validator.md`). 분석을 하지 않고, 방금 끝난 단계를
**정확성**(방법이 맞는가)과 **완결성**(남길 것을 남겼는가)으로 각각 1–5 점 채점합니다.

정확성 2점 이하면 `FAIL`(진행 금지), 둘 다 4점 이상이면 `PASS`, 나머지는 `WARN` 입니다.

루브릭은 Biomni 보충자료 Table S32–S33 에서 가져왔고, Section I 의 **출처 블라인드**
평가와 **수치 추적**(보고된 값을 원본 산출물까지 되짚기, 최소 3건) 절차도 그대로 옮겼습니다.
데이터에 없는 수치가 기록되어 있으면 정확성 1점입니다.

두 실험이 **같은 검증자**를 씁니다 — `setup.sh` 가 `.claude/agents/` 를 링크로 걸기 때문입니다.
기준이 달라지면 점수를 비교할 수 없습니다.

> **검증자도 Claude 입니다.** 5점이 옳다는 뜻은 아닙니다.
> 세션 C 에서 "검증자가 놓친 것" 을 찾는 것까지가 이 실습입니다.

## 이 프롬프트를 실험 변수로 쓰기

**한 줄을 지정으로 바꾸면 그대로 다른 실험이 됩니다.**

| 바꾸는 곳 | 무엇을 보게 되나 |
|---|---|
| `3.2` 를 `Harmony 로 stim 을 보정한다` 로 | 보정 여부가 결론을 얼마나 바꾸는지 |
| `4.1~4.2` 를 `resolution 0.5 를 쓴다` 로 | 여러 값을 비교하는 것이 실제로 결과를 바꾸는지 |
| `7.4` 를 지우면 | 자원·방법을 하나만 써도 같은 결론에 닿는지 |
| `R4`(검증 호출)를 지우면 | 자기 검증이 결과를 실제로 바꾸는지 |

이름만 주면 worktree 가 생기니, 프롬프트를 고쳐 다음 실험으로 넘기면 됩니다.

```bash
bash parallel_lab/setup.sh no-integration fixed-resolution
```
